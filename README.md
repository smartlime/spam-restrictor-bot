# 🛡️ Spam Restrictor Bot для Telegram

Телеграм-бот для автоматической защиты группы от спамеров путем ограничения прав новых участников. Сделано для группы, используемой для комментариев канала — комментаторы в нее не вступают, а боты делают это массово.

### Алгоритм работы:

1. **При вступлении нового участника:**
   - Автоматически ограничиваются права на отправку сообщений и медиа **для всех новых участников** без исключений.
   - Информация о пользователе сохраняется в БД.
   - Если вступил реальный пользователь - можно вручную вернуть ему права.

2. **Периодическая проверка (каждый час по умолчанию):**
   - Проверяются все ограниченные пользователи.
   - Если прошло 30 дней с момента ограничения — пользователь удаляется из группы.
   - Информация о удаленном пользователе сохраняется в БД.

3. **При повторном вступлении:**
   - Если пользователь был ранее удален — он немедленно блокируется без применения ограничений.


## Технические требования

- VPS с Debian/Ubuntu Linux
- Docker и Docker Compose установлены на сервере
- Telegram бот (токен от [@BotFather](https://t.me/BotFather))
- ID вашей группы (можно получить через [@getidsbot](https://t.me/getidsbot))

## Использование на VPS

### Установка
```bash
# Клонировать репо
git clone https://github.com/smartlime/spam-restrictor-bot
cd spam-restrictor-bot

# Настроить переменные окружения
cp .env.example .env
vim .env
```
   
### Настройка бота в Telegram

⚠️ **Обязательно до запуска:**

1. Добавить бота в группу

2. Сделать бота администратором с правами:
   - Удаление сообщений
   - Блокировка пользователей
   - Ограничение участников

### Запуск
```bash
docker compose up -d
```

### После запуска
Написать боту в ЛС — до этого момента он не сможет писать сообщения в личку.


## 🛠️ Локальная разработка

```bash
# Клонировать репо
git clone https://github.com/smartlime/spam-restrictor-bot
cd spam-restrictor-bot

# Настроить окружение
vf new spam-restrictor-bot
vf activate spam-restrictor-bot

# Настроить проект
cp .env.example .env.dev
vim .env.dev

# Для локального запуска и тестов
pip install -r requirements.txt

# Сборка в докере
docker-compose -f docker-compose.dev.yml build --no-cache

# Запуск в докере
docker-compose -f docker-compose.dev.yml up
```

### Тестирование
```bash
pytest -v tests/
```

## Переменные окружения

**Обязательные:**
- `BOT_TOKEN` - токен бота от @BotFather
- `GROUP_ID` - ID группы (отрицательное число)

**Опциональные:**
- `ADMIN_USER_ID` - ID администратора для уведомлений
- `RESTRICTION_PERIOD_DAYS` - дней до удаления (по умолчанию 30)
- `CHECK_INTERVAL_SECONDS` - интервал проверки в секундах (по умолчанию 3600)
- `NOTIFY_NO_USERS` - уведомлять когда нет новых для удаления: 0/1 (по умолчанию 0)
- `LOG_LEVEL` - уровень логирования (по умолчанию INFO)
